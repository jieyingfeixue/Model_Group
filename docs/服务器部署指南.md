# 服务器部署指南（云服务版）

> 当前项目在本地通过 Docker 运行全部服务。部署到服务器后：
> - PostgreSQL / Redis / 对象存储 → 使用云服务（不自己维护）
> - FastAPI + Celery Worker → 服务器上 Docker 运行
> - 前端 → Nginx 托管

---

## 一、架构变化

```
本地（现在）                    服务器（目标）
┌──────────┐                   ┌──────────────┐
│ Postgres │ Docker            │ 云数据库 RDS  │ 托管服务
│ Redis    │ Docker            │ 云 Redis      │ 托管服务
│ MinIO    │ Docker            │ 云 OSS/S3     │ 托管服务
│ API      │ Docker            │ API      Docker│ 自己维护
│ Celery   │ Docker            │ Celery   Docker│ 自己维护
│ Vite     │ dev server        │ Nginx         │ 自己维护
└──────────┘                   └──────────────┘
```

---

## 二、云服务选型参考

| 服务 | 阿里云 | 腾讯云 | AWS | Azure |
|------|--------|--------|-----|-------|
| 数据库(PostgreSQL) | RDS PostgreSQL | 云数据库 PostgreSQL | RDS | PostgreSQL Flexible Server |
| 缓存(Redis) | 云数据库 Redis | 云数据库 Redis | ElastiCache | Azure Cache for Redis |
| 对象存储(MinIO替代) | OSS | COS | S3 | Blob Storage |

> 建议先买同一云厂商的，内网互通，延迟低且不产生流量费。

## 三、后端配置修改

### 3.1 docker-compose.yml 简化

保留 API 和 Celery，删除 Postgres / Redis / MinIO 容器：

```yaml
services:
  api:
    build: ./backend
    container_name: api-server
    ports:
      - "8000:8000"
    environment:
      # 指向云数据库
      DATABASE_URL: postgresql://用户名:密码@云数据库地址:5432/detection_platform
      # 指向云 Redis
      REDIS_URL: redis://:密码@云Redis地址:6379/0
      # 指向云对象存储（如果需要兼容 S3 协议）
      MINIO_ENDPOINT: 对象存储Endpoint
      MINIO_ACCESS_KEY: 你的AccessKey
      MINIO_SECRET_KEY: 你的SecretKey
      MINIO_BUCKET: detection-platform
      MINIO_SECURE: "true"
      SECRET_KEY: 生成一个随机长字符串
    restart: unless-stopped

  celery-worker:
    build: ./backend
    container_name: celery-worker
    command: celery -A app.tasks.celery_app.celery_app worker --loglevel=info --concurrency=2
    environment:
      DATABASE_URL: postgresql://用户名:密码@云数据库地址:5432/detection_platform
      REDIS_URL: redis://:密码@云Redis地址:6379/0
      MINIO_ENDPOINT: 对象存储Endpoint
      MINIO_ACCESS_KEY: 你的AccessKey
      MINIO_SECRET_KEY: 你的SecretKey
      MINIO_BUCKET: detection-platform
      MINIO_SECURE: "true"
      SECRET_KEY: 同上
    restart: unless-stopped
```

### 3.2 需要云服务提供的信息

| 信息 | 从哪获取 | 示例 |
|------|---------|------|
| 数据库地址 | RDS 控制台 → 内网地址 | `pg-xxx.rds.aliyuncs.com` |
| 数据库端口 | RDS 控制台 | `5432` |
| 数据库账号/密码 | 创建实例时设置 | `platform_admin / 你的密码` |
| Redis 地址 | Redis 控制台 → 内网地址 | `r-xxx.redis.rds.aliyuncs.com` |
| Redis 端口 | Redis 控制台 | `6379` |
| Redis 密码 | 创建实例时设置 | `你的密码` |
| OSS Endpoint | OSS 控制台 | `oss-cn-shanghai.aliyuncs.com` |
| OSS AccessKey/SecretKey | RAM 访问控制 | `LTAI5t...` |

## 四、前端：构建 + Nginx

### 4.1 构建

```powershell
cd frontend
npm run build
```

### 4.2 Nginx 配置

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /path/to/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 五、数据迁移

### 5.1 数据库

```bash
# 本地导出
docker exec pg-local pg_dump -U postgres detection_platform > db_backup.sql

# 导入云数据库（用云服务商提供的连接信息）
psql -h 云数据库地址 -U 用户名 -d detection_platform -f db_backup.sql
```

### 5.2 图片文件

当前数据库里 `data_resources.file_path` 存的是 MinIO 路径（如 `/detection-platform/data/visible/sample.jpg`）。

迁移到云 OSS 后：
1. 用 OSS 迁移工具把本地 MinIO 数据同步到云 OSS
2. 不用改数据库——文件路径结构不变，只是访问入口从 `minio:9000` 变成云 OSS Endpoint
3. 后端 `MINIO_ENDPOINT` 指向云 OSS 后，`GET /api/images/{id}` 自动从云 OSS 读取

## 六、部署步骤总结

```
1. 购买云服务（PostgreSQL + Redis + OSS），开在同一区域
2. 创建数据库 → 设置白名单（允许服务器 IP 访问）
3. 在服务器上 git clone 代码
4. 修改 docker-compose.yml（去掉本地 Postgres/Redis/MinIO，配云服务地址）
5. 修改 .env 配置
6. 导入本地数据库到云数据库
7. 迁移 MinIO 数据到云 OSS
8. docker compose build && docker compose up -d
9. 前端 npm run build → Nginx 托管
10. 测试访问
```
