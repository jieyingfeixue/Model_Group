# LH 连续帧批量深度赋值方案

## 核心原则

深度真值来自地图目标 GPS 或雷达目标 GPS，不来自不可靠的相机内外参。
连续帧只负责保持物理目标身份 `target_id`，不能直接复制上一帧深度。
每一帧的最终深度都重新计算为：

```text
depth_m = distance(drone_gps_at_frame, target_gps)
```

## 推荐工作流

1. 打开一个 capture，在地图上只标记真实的物理目标，例如近、中、远三个楼群。
2. 同一楼群即使在图像中被拆成多个框，也只登记一个地图目标。
3. 重新打开数据集后，启动检查会自动：
   - 构建或更新 `target_depth_db.json`；
   - 扫描人工标注和 autofill 标注；
   - 按连续帧稳定 `target_id`；
   - 为每个已有图像框写入深度。
4. 在界面中打开“深度”叠加，只核验低置信度或身份跳变的框。

## 新匹配逻辑

- `Tall building`、`building`、`建筑物` 等标签会归一为同一类别。
- 不再要求图像框数量等于地图目标数量。
- 多个图像框可以共享同一 `target_id` 和同一物理目标。
- 每帧自动估计统一的相机水平偏航误差，吸收无人机抖动。
- 相邻帧使用上一帧的目标身份作为软约束，减少近邻目标之间跳变。
- 人工地图目标优先于自动雷达聚类目标。
- 航向角采用圆周插值，正确处理 `359° -> 0°`。

## 输出字段

`depth_labels/*.json` 中每个框包含：

```json
{
  "depth_m": 1234.5,
  "target_id": "manual_01234",
  "method": "gps_db_temporal",
  "confidence": 0.91,
  "az_diff_deg": 1.8,
  "camera_yaw_offset_deg": -3.5
}
```

核验时优先检查：

- `confidence < 0.65`
- `az_diff_deg > 12`
- 同一连续目标的 `target_id` 发生跳变
- 地图目标本身位置不准确

## 注意

`L:` 盘部分 autofill 目录当前存在“拒绝访问”或“文件/目录损坏且无法读取”错误。
批处理会跳过无法读取的文件，但这些目录需要在磁盘层面修复后才能完整覆盖。
