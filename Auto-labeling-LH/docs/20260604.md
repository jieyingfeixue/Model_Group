# 相机 2D 标注框深度自动赋值 — 技术方案（2026-06-04）

## 背景与约束

| 项目 | 说明 |
|------|------|
| 平台 | 无人机挂载（毫米波雷达 + 长焦相机） |
| 相机 | 长焦镜头，飞行时抖动剧烈；**无可靠内参**，仅有设计图近似相对位置 |
| 雷达 | mmWave UDP bin → mat（AntFrame，FZ包含方位角/仰角/距离/GPS/时间戳） |
| 现有标注 | 人工在相机图像上打 2D 框（LabelMe 格式，DA8679037 相机） |
| 目标 | 为每个 2D 框自动赋深度值，用于后续 3D 目标检测训练 |

## 现有工具（时间对齐基础）

| 文件 | 功能 |
|------|------|
| `tools/match_radar_camera_anchor.py` | W12 GPS 秒边界锚点 + 相机帧密化，每 FZ 包映射到最近相机帧（anchor CSV） |
| `tools/match_mat_camera.py` | 从 anchor CSV 聚合到 mat 级别，取中间 FZ 的相机帧对应关系（mat CSV） |

时间对齐精度已验证：好录制 capture 的 <33ms 覆盖率 ≥96%，中位误差 8–12ms（远低于相机 33ms/帧）。

---

## 核心洞察

直接投影方法行不通（无可靠内参 + 剧烈抖动 + 4km 距离压缩）。

可利用的稳定量：
1. **方位角排序**：相机长焦抖动+FoV 不准，但框在 u 方向的**相对顺序**基本不变；雷达方位角是物理测量值，完全可信。
2. **GPS + 姿态构成的视锥**：可粗过滤，把 4km 的雷达全场景 → 视锥内少量簇。
3. **图像标注框的数量/排列就是强先验**。

---

## 方案总览

### 方案 A：方位角排序匹配（核心，最不依赖标定）

```
雷达 BEV → DBSCAN 聚类 → 每簇质心方位角 az_radar[]
图像 2D 框 → u_center → az_cam = (u - W/2) / W * FoV_est
两组按方位角排序 → 求全局偏移 Δaz（吸收抖动+FoV误差）→ Hungarian匹配
匹配上的框 → 对应雷达簇 range 即为深度
```

- 抖动产生全局 Δaz，被全局偏移吸收，**不影响匹配结果**
- FoV 粗估值即使偏差 ±20% 也无影响
- 深度歧义由聚类解决：同方位不同距离的点分属不同簇，选最近簇或按信号强度选最显著簇

### 方案 B：单目深度 + 雷达锚点校准

```
Depth Anything V2（models/depth_anything_v2_vits.pth）→ 相对深度图 D_rel
用方案A的可信匹配对拟合：D_abs = a·D_rel + b
对所有框：depth = median(D_abs[框内像素])
```

- 覆盖雷达漏检的小目标/遮挡目标
- 长焦图像需 patch 级推理，注意 resize 影响

### 方案 C：GPS 视锥粗过滤（方案 A 前置步骤）

```
IMU yaw/pitch/roll + GPS + 设计图相对位置 → 构造视锥（FoV 留 ±30% margin）
雷达点转 ENU → 转机体系 → 过滤进视锥的点
结果传入方案 A
```

- 把 4km 全场景缩减为视锥内几十个簇，匹配鲁棒性大幅提升

### 方案 D：跨帧时序累积（提精度）

```
图像 tracker（ByteTrack/SAM2）从标注帧前后跟踪每个框
每帧方案A估深度 → 卡尔曼滤波累积
回填到人工标注帧 → 平滑低方差深度
```

- 悬停场景特别有效，同一目标 N 帧中位数压掉抖动残差

### 方案 E：半监督学习模型（终态）

```
方案A+B 自动产生 (图像patch, 雷达BEV扇区, 深度标签) 三元组
训轻量回归网络
泛化后不再依赖每帧标定/匹配
```

### 方法 1 优化（补充）

| 优化点 | 方法 |
|--------|------|
| 深度歧义 | 框内雷达点按 range 做 1D DBSCAN → 按 (点数×强度/range²) 打分 → 取最高分簇 |
| 自标定 | 把 (fx, cx, R, t) 当优化变量，最大化"雷达点投影到框内" → 梯度下降 |
| 抖动补偿 | 光流法估每帧相对旋转（纯旋转分量），补偿 u 坐标后再匹配 |

## 实施路径

### Step 1（当前）：方案 A + 1D range 聚类
- 工具：`tools/assign_depth_azimuth.py`
- 输入：mat 文件 + LabelMe JSON（DA8679037） + match_mat_camera.csv
- 输出：每个 capture 目录下 `depth_labels/` 文件夹，每帧一个 JSON，含 `{box_id, depth_m, confidence, az_match_delta}`
- 评估指标：匹配率（框有深度的比例）、σ_depth（同目标跨帧标准差）

### Step 2：方案 C（视锥过滤）
- 读 nav100/IMU 的 yaw+pitch+roll，构造视锥过滤器
- 在 Step 1 的聚类之前加前置过滤

### Step 3：方案 D（跨帧时序累积）
- 使用 OpenCV KCF/光流 做简单帧间目标跟踪
- 累积同一目标的多帧深度估计，输出平滑深度

### Step 4：方案 B（单目深度校准）
- 复用现有 `src/fusion/depth_anything_metric.py`
- 用 Step 1/2/3 产生的高置信匹配对做 per-capture 线性校准

### Step 5：方案 E（学习模型）
- 使用 Step 1-4 产生的全量标签训练
- 模型存于 `models/`

## 2D 标注格式约定

- 格式：LabelMe JSON，存于 annot_root 下 `hikrobot_camera__DA8679037__image_raw/*.json`
- 文件名 stem 与图像文件名 stem 一一对应（含时间戳 `_tNNNNNN.NNN`）
- 字段：`shapes[].label`, `shapes[].points` (矩形两点 [[x0,y0],[x1,y1]])
- 已在 `src/io/adapters/lh_adapter.py` 中通过 `_LABELME_GLOBAL_CACHE` 支持加载

---

## 目录输出约定

```
L:/LH_data_all_sensor/{date}/{capture}/
    match_radar_camera_anchor.csv   ← FZ 级时间对齐
    match_mat_camera.csv            ← mat 级时间对齐
    depth_labels/                   ← 新增：深度赋值结果
        {mat_stem}.json             ← 每 mat 一个，含框深度信息
```

每条记录格式：
```json
{
  "mat_name": "mmwave_..._AntFrame003_FZ007718-009689.mat",
  "camera_name": "hikrobot_camera__DA8679037__image_raw_000287_t000010.718.jpg",

    {

      "depth_m": 320.5,
      "confidence": 0.85,
      "az_match_delta_deg": 1.2,
      "radar_range_m": 320.5,
      "method": "azimuth_match"
    }
  ]
}
```
